# 数据库及接口设计文档

> 本文件基于系统设计文档第 4/5 章独立整理，用于课程交付。完整设计见 [系统设计文档](02-系统设计文档.md)。

## 1. 数据库设计

技术栈：PostgreSQL 16 + PostGIS 3.6.2（地理空间） + Prisma 5 ORM。共 6 张数据表 + 4 个枚举。Schema 修改统一由后端主责成员执行 `prisma migrate dev`。

### 1.1 枚举

| 枚举 | 取值 | 用途 |
|---|---|---|
| OrderStatus | PENDING, ASSIGNED, IN_TRANSIT, DELIVERED, FAILED, CANCELLED | 订单生命周期 |
| TaskStatus | CREATED, ASSIGNED, STARTED, COMPLETED, CANCELLED | 调度任务状态机 |
| VehicleStatus | IDLE, ON_DUTY, MAINTENANCE | 车辆可用性 |
| DriverStatus | AVAILABLE, ON_DUTY, OFF | 司机可用性 |

### 1.2 数据表

| 表 | 关键字段 | 说明 |
|---|---|---|
| Customer | id, name, phone, address, lng, lat, timeWindowStart, timeWindowEnd, serviceTime | 客户含经纬度与时间窗 |
| Order | id, customerId(FK), weight, volume, status, priority | 订单归属客户 |
| Vehicle | id, plate(唯一), capacityW, capacityV, status | 车辆运力 |
| Driver | id, name, phone, license(唯一), status | 司机 |
| DispatchTask | id, vehicleId(FK), driverId(FK), status, startTime, endTime, totalDist, totalCost | 调度任务 |
| DispatchStop | id, taskId(FK), orderId(FK), seq, lng, lat, arrived | 任务停靠点（VRP 输出） |

### 1.3 实体关系

- Customer 1 ── N Order
- Order 1 ── N DispatchStop
- Vehicle 1 ── N DispatchTask
- Driver 1 ── N DispatchTask
- DispatchTask 1 ── N DispatchStop

### 1.4 地理空间

客户经纬度（lng/lat）由百度地图录入，入库时转为 PostGIS `POINT` 类型。后端距离计算使用 `ST_DistanceSphere`（球面直线距离，米），不生成真实道路导航路径。VRP 距离矩阵一次查询构造，对称矩阵。

## 2. 接口设计

### 2.1 风格

- RESTful，路径复数（/customers、/orders、/vehicles、/drivers、/dispatch-tasks）
- 统一 5 个 CRUD 接口：GET /、GET /:id、POST /、PATCH /:id、DELETE /:id
- 统一错误格式：`{ statusCode, message, error }`（NestJS 默认）
- Swagger 挂载在 `http://localhost:3000/api/docs` ，前端通过此契约对接

### 2.2 模块接口清单

| 模块 | 接口 |
|---|---|
| /customers | GET /、GET /:id、POST /、PATCH /:id、DELETE /:id |
| /orders | GET /、GET /:id、POST /、PATCH /:id、DELETE /:id |
| /vehicles | GET /、GET /:id、POST /、PATCH /:id、DELETE /:id |
| /drivers | GET /、GET /:id、POST /、PATCH /:id、DELETE /:id |
| /dispatch-tasks | GET /、GET /:id、POST /、PATCH /:id、DELETE /:id |
| /vrp | POST /optimize（预览）、POST /confirm（确认） |

### 2.3 VRP 特殊接口

- `POST /vrp/optimize`：输入订单列表、车辆列表、仓库坐标，返回三种算法的路线预览。只读不落库。
- `POST /vrp/confirm`：校验预览未过期、资源可用后，在 Serializable 事务中分配车辆与司机并生成调度任务。事务提交后通过 Socket.IO 广播通知。

### 2.4 实时推送

Socket.IO 命名空间 `/tracking`：任务状态变更时推送事件至前端，前端收到后重新查询任务快照。断线期间不补发，重连后以 REST 快照恢复。
