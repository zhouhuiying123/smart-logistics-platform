# 智慧物流配送与路径优化平台 — 项目总结报告

> 小组：周慧莹（组长）、徐艳茜、任祖如怡 · 报告日期：2026-11-21

## 1. 项目概述

本项目面向中小物流企业的配送调度场景，实现「基础数据管理 → 订单管理 → VRP 路径优化 → 调度任务执行 → 实时跟踪 → 统计分析」的完整业务闭环，属于同时具备软件系统能力与核心算法难度的综合开发项目。

- 软件系统：NestJS 10 + Prisma 5 + PostgreSQL 16/PostGIS 后端（:3000，Swagger 见 `/api/docs`）；Vue 3 + Vite + TypeScript 调度员业务端（:5173，数据/地图/任务/仪表盘四页）与零框架静态管理员控制台（:3000/admin），双端共享同一 RESTful API 契约。
- 核心算法：CVRP-GA、VRPTW-GA、NSGA-II 三种启发式算法，均集成 Clarke-Wright Savings 初始解与 2-opt 局部搜索；距离矩阵由 PostGIS `ST_DistanceSphere` 计算，算法结果直接驱动系统的路径优化与调度功能。

## 2. 主要工作过程

项目按「契约先行、并行开发、联调收尾」推进，全程遵循 main/dev 分支保护与 PR + Review 合并流程：

1. **冻结契约**：三人先约定 VRP 接口、Socket.IO 事件、RESTful 风格（复数路径 + 统一错误格式）与 Prisma 统一访问规则，此后前后端、算法与业务模块并行开发互不阻塞。
2. **并行实现**：五大业务模块、三种算法与实时推送、前端四页与仪表盘分别由对应主责成员推进；数据库 Schema 统一由后端主责成员执行迁移，避免结构冲突。
3. **联调与测试**：补齐单元/接口/e2e 测试，完成 27 组算法对比实验，缺陷逐项记录并闭环（详见第 5 节）。
4. **文档与答辩收尾**：统一测试口径、复跑实验数据、完成答辩 PPT 与验收自查。

## 3. 项目成果

### 3.1 功能成果

项目形成了可本地运行的 Vue 3 + NestJS + Prisma + PostgreSQL/PostGIS 系统，包含：

- 客户、订单、车辆、司机基础数据的增删改查，并对有引用的数据和执行中的资源做状态保护。
- CVRP-GA、VRPTW-GA、NSGA-II 路线优化预览、方案选择、不同司机分配及事务确认。
- 百度地图展示客户点、优化预览、调度任务路线及配送中车辆的模拟位置（沿路线按任务开始时间插值，每 2 秒刷新）；接口坐标由 WGS84 转为百度 BD09。
- 调度任务开始、完成、取消及订单/车辆/司机状态联动。
- `/tracking` Socket.IO 命名空间发送任务状态更新，前端收到后重新查询任务。
- 运营仪表盘和空数据库演示数据脚本。

### 3.2 验证结果

最近一次本地自动检查通过（2026-11-02）：后端 7 个 Jest 套件、35 个测试（14.6s）；后端 e2e 3 个套件、5 个测试（7.5s，专用 logistics_test 数据库，覆盖确认方案到任务完成的完整状态联动）；Nest 后端构建；Vue 类型检查与 Vite 生产构建；独立 Socket.IO 握手和通知传输；演示 seed 脚本语法检查；百度地图 AK 配置后底图、订单点与路线渲染正常。

按 docs/05 口径：单元 24 项 + 接口 11 项 = 35 项，与 Jest 报告一致；e2e 的 5 项按被测层级拆入接口 3 项与系统 2 项。四类用例表与缺陷记录合计 55 条（单元 24、接口 14、系统 6、性能 4、缺陷 7），全部缺陷已闭环。算法实验见 docs/06：27 组实验中 6 单规模求解 57.3~112.1ms，20 单紧时间窗 250.4~353.4ms，50 单紧时间窗最慢 1079.0ms（VRPTW-GA），满足交互式调度的时限要求。

e2e 会创建、修改、删除业务记录，只允许在专用测试库（如 logistics_test）运行，禁止连接演示库或生产库。生产部署、并发压力、鉴权与安全性验收尚未执行。

## 4. 与原计划的偏差

| 原计划 | 实际落地 | 调整原因 |
|---|---|---|
| 地图选型高德/Leaflet | 百度地图 BMapGL（WebGL 版） | WebGL 渲染与覆盖层能力更完整，AK 按 Referer 域名校验便于三人本地协作 |
| cvrp-ga.ts、vrptw-ga.ts 两个独立算法文件 | 合并为 cvrp.ts 混合求解器，按 timing 入参切换 CVRP-GA/VRPTW-GA | 两算法共享编码、交叉、变异与 2-opt 骨架，拆分会产生大量重复代码 |
| 5 张独立管理页 + 独立跟踪页 | DataView 单页管理基础数据，跟踪演示并入地图页，另新增零框架 admin 控制台 | 基础数据表单高度同构合并去重；控制台用于验证前后端分离架构价值 |
| 引入 Redis | Docker Compose 已提供，业务尚未接入 | 优先级让位于状态机事务与测试收尾 |
| 与精确算法做对比实验 | 明确弃用精确算法，三算法均属启发式遗传系列 | 精确算法在节点数超过 100 后呈指数级不可用，与课程性能要求冲突 |

## 5. 主要问题及解决过程

7 项缺陷完整记录于 [测试文档](05-测试文档.md)（D-01~D-07），典型四例：

1. **并发竞态**：调度任务创建/更新时车辆与司机可能被重复分配 → 改用 Serializable 隔离级别 + 条件式 updateMany 原子抢占，消除 TOCTOU 竞态。
2. **通知时序**：事务回滚后通知已发出造成状态不一致 → 通知统一改为事务提交后发送，并用 fake timers 验证时序。
3. **BMapGL 未定义**：SDK 加载地址错误导致地图脚本未就绪 → 固定为官方 WebGL 加载地址并增加就绪等待。
4. **e2e 超时**：AppModule 完整初始化超出 Jest 默认 5 秒 → 超时调至 120 秒并改用专用 logistics_test 测试库。

## 6. 项目亮点

1. 双端架构验证前后端分离价值：同一 API 契约同时服务 Vue 业务端与零框架管理台。
2. 状态机强一致：Serializable + 条件式更新保证订单/车辆/司机状态与任务状态原子联动，通知严格在提交后发出。
3. 三算法共用同一输入输出契约，切换算法业务层零改动，实验数据可复现（docs/06 附图表复现命令）。
4. 后端距离计算完全不依赖地图服务（PostGIS 直算），地图 AK 泄露不影响核心调度功能。
5. 测试证据链完整可复核：55 条用例与缺陷记录、复现命令、实验原始数据（results.json/summary.csv）齐备。

## 7. 不足与改进

- **距离模型**：使用球面直线距离，不生成真实道路导航路径 → 后续接入路径规划服务。
- **车辆定位**：配送中车辆位置为前端沿路线按开始时间插值的模拟轨迹，非真实 GPS → Socket.IO 通道已预留，可接真实定位上报。
- **安全**：无用户鉴权与公网部署，不应承载真实业务数据 → 计划引入 JWT + 角色权限体系。
- **性能验收**：并发压力用例（PT-04）尚未执行，50 单以上规模仅有算法层实验数据 → 后续补充压测。
- **缓存**：Redis 未接入业务，任务查询尚未利用缓存优化。
