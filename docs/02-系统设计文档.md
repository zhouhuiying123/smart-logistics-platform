# 智慧物流配送与路径优化平台 — 系统设计文档

## 1. 项目概述
后端负责客户、订单、车辆、司机、调度任务的管理与状态流转，为后续 VRP 路径优化算法与实时跟踪提供数据与接口支撑。

## 2. 技术栈
- 框架：NestJS 10 + TypeScript
- ORM / 数据库：Prisma 5 + PostgreSQL（PostGIS）
- 缓存：Redis（预留）
- 接口文档：Swagger / OpenAPI，地址 http://localhost:3000/api/docs
- 参数校验：class-validator + 全局 ValidationPipe
- 测试：Jest + supertest（e2e）

## 3. 总体架构
采用经典分层，自上而下：

HTTP 请求 -> Controller（路由、参数校验）-> Service（业务逻辑、状态联动）-> PrismaService -> PostgreSQL

backend/src 目录结构：
- prisma/        全局 PrismaService
- customers/     客户模块
- orders/        订单模块
- vehicles/      车辆模块
- drivers/       司机模块
- dispatch-tasks/ 调度任务模块（含状态流转联动）
- app.module.ts  根模块，统一注册上述模块

## 4. 数据库设计
共 6 张数据表 + 4 个枚举。

### 4.1 枚举
| 枚举 | 取值 |
|---|---|
| OrderStatus | PENDING, ASSIGNED, IN_TRANSIT, DELIVERED, FAILED, CANCELLED |
| TaskStatus | CREATED, ASSIGNED, STARTED, COMPLETED, CANCELLED |
| VehicleStatus | IDLE, ON_DUTY, MAINTENANCE |
| DriverStatus | AVAILABLE, ON_DUTY, OFF |

### 4.2 数据表
| 表 | 关键字段 | 说明 |
|---|---|---|
| Customer | id, name, phone, address, lng, lat, timeWindowStart, timeWindowEnd, serviceTime | 客户含经纬度与时间窗 |
| Order | id, customerId(FK), weight, volume, status, priority | 订单归属客户 |
| Vehicle | id, plate(唯一), capacityW, capacityV, status | 车辆运力 |
| Driver | id, name, phone, license(唯一), status | 司机 |
| DispatchTask | id, vehicleId(FK), driverId(FK), status, startTime, endTime, totalDist, totalCost | 调度任务 |
| DispatchStop | id, taskId(FK), orderId(FK), seq, lng, lat, arrived | 任务停靠点（VRP 输出） |

### 4.3 实体关系
- Customer 1 ── N Order
- Order 1 ── N DispatchStop
- Vehicle 1 ── N DispatchTask
- Driver 1 ── N DispatchTask
- DispatchTask 1 ── N DispatchStop

## 6. 核心状态机：调度任务联动
状态流转：CREATED -> ASSIGNED -> STARTED -> COMPLETED（任一中间态可 CANCELLED）。

| 流转 | 任务状态 | 车辆状态 | 司机状态 |
|---|---|---|---|
| 创建 | CREATED | 不变 | 不变 |
| CREATED -> ASSIGNED | ASSIGNED | IDLE -> ON_DUTY | AVAILABLE -> ON_DUTY |
| ASSIGNED -> STARTED | STARTED | 保持 ON_DUTY | 保持 ON_DUTY |
| STARTED -> COMPLETED | COMPLETED | ON_DUTY -> IDLE | ON_DUTY -> AVAILABLE |
| -> CANCELLED | CANCELLED | ON_DUTY -> IDLE | ON_DUTY -> AVAILABLE |
