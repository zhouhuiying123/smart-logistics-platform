# 算法设计文档

## 算法选型背景

传统 VRP 精确求解算法（如分支定界、动态规划、混合整数规划）时间复杂度呈指数级增长，当配送节点数量超过 100 时求解效率极低，几乎无法使用。因此本项目**不使用精确算法**，全部采用启发式遗传系列算法（CVRP-GA、VRPTW-GA、NSGA-II）作为核心求解器，用可接受的时间代价换取高质量可行解。

## 范围

本模块输入订单、车辆、仓库坐标，输出路线预览。确认预览后才生成调度任务。距离为球面距离（米），不代表道路行驶距离；费用 totalCost 为 null。FOUND 表示完整容量可行，不保证全局最优，也不保证没有迟到。

## 距离矩阵

线上 distance-matrix.ts 使用参数化 PostGIS ST_DistanceSphere 计算点间距离，构造对称矩阵。仓库和客户坐标参与计算。经纬度、数量等由 DTO 校验。ST_DWithin 是邻域筛选函数，当前流程不需要邻域筛选；若验收要求同时使用，应与组长明确，不把它写成已经实现。

## CVRP 遗传算法

染色体为订单排列；解码时按车辆重量和体积容量分配订单。评价优先减少未分配订单，再比较距离。初始化保留基础排列并生成随机排列；使用三元锦标赛选择、保留顺序的片段交叉、交换变异。

| 参数 | 当前值 |
|---|---:|
| 种群 | 40 |
| 迭代 | 120 |
| 精英保留 | 2 |
| 交换变异概率 | 0.3 |
| 默认随机种子 | 42 |

这是启发式搜索；搜索没有找到完整方案不等于数学上证明问题无解。

## VRPTW 时间窗

在 CVRP 中加入时间评估。时间单位为午夜起分钟数，可以超过 1440。

- 行驶分钟数 = 距离米数 / (速度 km/h × 1000 / 60)。
- 服务开始 = max(到达时间, 时间窗开始)。
- 等待 = max(时间窗开始 − 到达时间, 0)。
- 迟到 = max(服务开始 − 时间窗结束, 0)。
- 离开 = 服务开始 + 每订单服务时长。
- 评价分数 = 总距离 + penaltyPerMinute × 总迟到分钟数。

默认出发 480（08:00）、速度 30 km/h、每迟到分钟惩罚 1000。惩罚是算法权重，不是人民币。采用软时间窗，允许以惩罚方式处理迟到；返回仓库的行驶时间计入路线结束时间。

## NSGA-II 多目标

最小化总距离、使用车辆数、总迟到分钟数。编码包含订单排列及车辆分配基因，解码进行容量修复。通过约束优先的非支配排序、拥挤度选择和父子代合并精英保留产生候选方案。

种群 48、迭代 100、订单交换变异概率 0.4，车辆基因变异概率随订单数量变化。返回本次搜索的非支配方案集合，不保证真实全局 Pareto 前沿。一个方案优于另一个方案，指全部目标不更差且至少一个目标更好。

## 系统接口与一致性

POST /vrp/optimize 只预览；确认流程检查预览是否过期、数据是否变化、司机和车辆是否可用，在事务中分配资源并生成任务。共享 PrismaService 访问数据库。数据库操作成功后再广播任务通知，事务失败不应发送成功通知。

## 实现位置与验证

实现位于 backend/src/vrp 的 distance-matrix.ts、cvrp.ts、nsga2.ts、vrp.service.ts 和 confirm.service.ts。VRPTW 与 CVRP 共用求解器中的时间评估逻辑，并非独立 vrptw-ga.ts。

已有用户提供的实验记录为 27 次 PASS。本次增加迭代观察回调用于记录曲线；最新代码通过单元测试、编译检查及独立 Socket.IO 传输测试；团队前端页面仍需联调。文件名与分工表不同不影响功能，但交付时应说明对应关系。
