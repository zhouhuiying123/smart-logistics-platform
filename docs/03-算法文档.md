## 算法选型背景

传统 VRP 精确求解算法（如分支定界、动态规划、混合整数规划）时间复杂度呈指数级增长，当配送节点数量超过 100 时求解效率极低，几乎无法使用。因此本项目**不使用精确算法**，全部采用启发式遗传系列算法（CVRP-GA、VRPTW-GA、NSGA-II）作为核心求解器，用可接受的时间代价换取高质量可行解。

## VRPTW 时间窗

在 CVRP 中加入时间评估。时间单位为午夜起分钟数，可以超过 1440。

- 行驶分钟数 = 距离米数 / (速度 km/h × 1000 / 60)。
- 服务开始 = max(到达时间, 时间窗开始)。
- 等待 = max(时间窗开始 − 到达时间, 0)。
- 迟到 = max(服务开始 − 时间窗结束, 0)。
- 离开 = 服务开始 + 每订单服务时长。
- 评价分数 = 总距离 + penaltyPerMinute × 总迟到分钟数。

默认出发 480（08:00）、速度 30 km/h、每迟到分钟惩罚 1000。惩罚是算法权重，不是人民币。采用软时间窗，允许以惩罚方式处理迟到；返回仓库的行驶时间计入路线结束时间。

## NSGA-II 多目标

最小化总距离、使用车辆数、总迟到分钟数。编码包含订单排列及车辆分配基因，解码进行容量修复。通过约束优先的非支配排序、拥挤度选择和父子代合并精英保留产生候选方案。

## 主要数学公式

记 n 为订单数、m 为车辆数、d(i,j) 为点 i 与 j 的球面距离（米），订单 i 的时间窗为 [e_i, l_i]（午夜起分钟），服务时长 s_i，车速 v，迟到罚金 λ。

**1. Clarke-Wright 节约值**（CVRP-GA 初始解，按降序用并查集合并）：

$s(i,j) = d(0,i) + d(0,j) - d(i,j)$

**2. VRPTW 时间推演**（单位：分钟）：

$t(i,j) = \frac{d(i,j) \cdot 60}{v \cdot 1000},\quad a' = \max(a,\, e_i)$

$w = \max(e_i - a,\, 0),\quad lt_i = \max(a' - l_i,\, 0),\quad dep = a' + s_i$

其中 a 为到达时刻，w 为等待，lt 为迟到，dep 为离开时刻。

**3. VRPTW 适应度函数**（CVRP 即 λ·Σlt 恒为 0 的特例）：

$F = \sum_{r \in R} d_r + \lambda \sum_{r \in R}\sum_{i \in r} lt_i,\quad \lambda = 1000$

**4. 自适应变异率**（g 为当前代，G = 200，线性衰减）：

$p_m(g) = 0.15 - (0.15 - 0.02)\cdot \frac{g}{G}$

**5. Pareto 支配关系**（NSGA-II 三目标 f = (Σd, 使用车辆数, Σ迟到)）：

$x \prec y \iff \forall k:\ f_k(x) \le f_k(y)\ \wedge\ \exists k:\ f_k(x) < f_k(y)$

约束优先：先比较未分配订单数 |missing|，小者占优；|missing| 相同再按上式支配关系排序。

**6. 拥挤度距离**（同一前沿内，边界解为 +∞）：

$crowd(i) = \sum_{k=1}^{3} \frac{f_k(i{+}1) - f_k(i{-}1)}{f_k^{\max} - f_k^{\min}}$

**7. 确定性伪随机数（LCG）**：

$x_{t+1} = (1664525 \cdot x_t + 1013904223) \bmod 2^{32}$

同一随机种子结果完全可复现，docs/06 实验与单元测试的确定性断言均依赖该性质。

## 算法流程图与伪代码

整体数据流（从输入到任务确认）：

```text
订单/车辆/坐标
   │  PostGIS ST_DistanceSphere（一次查询）
   ▼
n×n 球面距离矩阵
   │
   ├─► Clarke-Wright Savings 初始解 ──► GA 主循环 ──► 逐路线 2-opt ──► CVRP-GA / VRPTW-GA 单方案
   │        （种群80/迭代200/OX交叉/自适应变异/精英保留4）
   └─► NSGA-II 主循环 ──────────────────────► Pareto 解集
            （种群60/迭代150/非支配排序/拥挤度选择）
   ▼
路线预览（POST /vrp/optimize，只读不落库）
   ▼
确认事务（预览过期/资源可用性校验 → 分配车辆与司机 → 生成任务 → 提交后广播通知）
```

CVRP-GA / VRPTW-GA 主流程伪代码：

```text
输入: 订单集 n、车辆集 m、距离矩阵 D、可选 timing
 1: seed ← Savings(D)                    # 节约值降序 + 并查集容量合并
 2: P[0] ← decode(seed); P[1] ← decode(自然序); P[2..79] ← decode(randperm)
 3: for g = 1 .. 200:
 4:     按 (未分配订单数↑, F↑) 对 P 排序
 5:     pm ← 0.15 − 0.13 × g/200
 6:     next ← P[0..3]                   # 精英保留 4 个
 7:     while |next| < 80:
 8:         a, b ← 三元锦标赛选择
 9:         child ← OX(a, b) 以 0.85 概率，否则复制较优者
10:         以 pm 概率对 child 做交换或逆序变异（各 50%）
11:         next.push(decode(child))     # 贪心最小增量插入 + 逐路线 2-opt
12:     P ← next
13: return P 最优解

decode(genes): 依基因序逐订单在容量可行车辆中选「距离增量（VRPTW 另加 λ×迟到）」最小者插入；
全部插入后对每条路线执行 2-opt 消除交叉并重算距离与时间表。
```

NSGA-II 主流程伪代码：

```text
输入: 同 CVRP，另需 timing
 1: P ← 60 个个体（订单排列基因 + 车辆分配基因）
 2: for g = 1 .. 150:
 3:     解码并容量修复，目标向量 f ← (Σd, 使用车辆数, Σ迟到)
 4:     C ← 父子合并，快速非支配排序（|missing| 优先）分层 F1, F2, …
 5:     newP ← 依 F1、F2… 整层放入，溢出层按拥挤度距离截断
 6:     拥挤度锦标赛选择 → 交叉 + 双变异（排列交换 0.15 / 分配变异 0.20）生成子代
 7:     P ← newP
 8: return 第一前沿的非支配解集
```

## 时间与空间复杂度分析

记 n 订单数、m 车辆数、P 种群规模、G 迭代代数、k = 3（目标数）、L 为单路线长度。

**时间复杂度**

| 组件 | 复杂度 | 本项目参数 |
|---|---|---|
| 距离矩阵构造 | O(n²) | 一次 PostGIS 查询，对称矩阵 |
| Savings 初始解 | O(n² log n) | n(n−1)/2 个节约对排序 + 并查集合并 |
| 单个体解码 | O(n·m) | 每订单扫描全部车辆取最小增量 |
| 单路线 2-opt | O(L³ · r) | 每轮 O(L²) 邻域 × O(L) 段重建，改进轮数 r 实际很小 |
| GA 单代 | O(P log P) + O(P·(n·m + 2-opt)) | P = 80 |
| CVRP-GA / VRPTW-GA 整体 | O(G·P·n·m) | G = 200，共 16,000 次解码评价 |
| NSGA-II 非支配排序 | O(k·P²) | k = 3, P = 60 |
| NSGA-II 整体 | O(G·(P·n·m + k·P²)) | G = 150，共 9,000 次评价 |

评价次数由固定超参数决定，与 n 无关；整体耗时随 n 的增长主要来自解码与 2-opt，实测趋势一致：6 单 57.3~112.1ms，50 单最慢 1079.0ms（见 docs/06）。对比精确算法（分支定界、状态压缩 DP 最坏指数级），n = 50 时已不可行，这是选型背景的定量依据。

**空间复杂度**

| 组件 | 复杂度 | 说明 |
|---|---|---|
| 距离矩阵 | O(n²) | 实现注释以 Float32Array/TypedArray 优化大数据内存 |
| 种群存储 | O(P·n) | 每个体一个长度 n 的排列 |
| Savings 列表 | O(n²) | 排序使用后即释放 |
| NSGA-II 分层与支配计数 | O(P²) | beats 邻接表 + 计数数组 |

> 注：2-opt 的 O(L³·r) 为最坏情形；实验规模下 r 与 L 都很小，实测 50 单最慢 1079.0ms，满足交互式预览的时限要求。

## 系统接口与一致性

POST /vrp/optimize 只预览；确认流程检查预览是否过期、数据是否变化、司机和车辆是否可用，在事务中分配资源并生成任务。共享 PrismaService 访问数据库。数据库操作成功后再广播任务通知，事务失败不应发送成功通知。
