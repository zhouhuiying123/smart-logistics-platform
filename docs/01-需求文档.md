## 1. 引言

### 1.1 项目背景与目的

传统物流配送依赖人工排线，存在路线不合理、车辆利用率低、无法满足客户时间窗等问题。

**算法背景补充**：传统 VRP 精确求解算法时间复杂度呈指数级增长，当配送节点数量超过 100 时算法求解效率极低，几乎无法使用。因此本项目放弃精确求解算法，采用启发式遗传系列算法（遗传算法 GA、多目标 NSGA-II）自动生成配送路线。

本项目旨在构建一个**智慧物流配送与路径优化平台**，通过 CVRP-GA、VRPTW-GA、NSGA-II 智能优化算法自动生成配送路线，并提供订单、车辆、司机、调度任务的全流程管理与实时跟踪能力。

**区分优化阶段**：
① 方案选型优化【本阶段需求文档已完成】：选用启发式遗传算法，规避精确算法指数时间复杂度问题；
② 代码参数调优【开发阶段执行】：CVRP-GA、VRPTW-GA、NSGA-II 三个算法全部需要进行内部参数调参，保障求解速度和解的质量。

### 1.2 项目范围

| 包含 | 不包含 |
|---|---|
| 客户/订单/车辆/司机/调度任务的管理与状态流转 | 真实计费、结算、发票 |
| VRP 路径优化（CVRP-GA / VRPTW / NSGA-II） | 真实车辆 GPS 硬件接入 |
| WebSocket 配送状态实时推送 | 用户注册/登录鉴权体系（课程演示环境） |
| **百度地图 API 地图可视化**（课程演示使用开发者免费配额，商用场景会产生 API 调用费用）、管理页面、统计仪表盘 | 多租户、国际化 / 生产调度管理、库存管理（本系统专注配送路径调度，上游生产仓储不在项目范围） |

### 1.3 术语定义

| 术语 | 说明 |
|---|---|
| VRP | Vehicle Routing Problem，车辆路径问题 |
| CVRP | 带容量约束的 VRP（车辆载重/容积限制） |
| VRPTW | 带时间窗约束的 VRP（客户要求送达时间区间） |
| 时间窗 | 客户可接受服务的起止时间 [timeWindowStart, timeWindowEnd] |
| 调度任务 | 一次配送执行单元：车辆 + 司机 + 一组有序停靠点 |
| 停靠点（DispatchStop） | 调度任务中按序访问的订单节点，即算法输出的路线 |

## 3. 功能需求

### 3.1 功能总览

| 编号 | 功能模块 | 说明 | 优先级 |
|---|---|---|---|
| FR-1 | 基础数据管理 | 客户、车辆、司机的增删改查 | 高 |
| FR-2 | 订单管理 | 订单录入、状态流转、关联客户 | 高 |
| FR-3 | 调度任务管理 | 任务创建、分配、状态流转联动 | 高 |
| FR-4 | VRP 路径优化 | 输入订单与车辆 → 输出最优配送路线，支持 **CVRP-GA / VRPTW-GA / NSGA-II 三种启发式算法** | 高 |
| FR-5 | 配送实时跟踪 | WebSocket 推送任务/车辆状态 | 中 |
| FR-6 | 地图可视化 | 客户点、路线、车辆位置在**百度地图**上展示 | 中 |
| FR-7 | 统计分析仪表盘 | 配送完成率、车辆利用率、平均耗时等 | 中 |

### 3.2 FR-1 基础数据管理

**客户管理**
- 支持新增/修改/删除/查询客户，字段：名称、电话、地址、经纬度（lng/lat）、服务时间窗（起止）、单点服务时长
- 经纬度为路径优化与地图展示的必要字段，录入时必填校验

**车辆管理**
- 字段：车牌号（唯一）、载重上限 capacityW、容积上限 capacityV、状态
- 状态机：`IDLE（空闲）→ ON_DUTY（执行任务中）→ IDLE`；`MAINTENANCE（维修中）`车辆不可被分配任务

**司机管理**
- 字段：姓名、电话、驾驶证号 license（唯一，重复返回 409）、状态
- 状态机：`AVAILABLE（可用）↔ ON_DUTY（执勤中）↔ OFF（休息）`

### 3.3 FR-2 订单管理

- 字段：所属客户（必填，外键）、货重 weight、体积 volume、优先级 priority、状态
- 状态机：`PENDING（待分配）→ ASSIGNED（已分配）→ IN_TRANSIT（配送中）→ DELIVERED（已送达）`；任一阶段可 `FAILED` / `CANCELLED`
- 仅 `PENDING` 状态订单可参与路径优化与调度分配

### 3.4 FR-3 调度任务管理

- 创建任务：选择车辆 + 司机 + 关联订单集合
- 状态机：`CREATED → ASSIGNED → STARTED → COMPLETED`，任一中间态可 `CANCELLED`
- **状态联动规则**（核心业务规则）：

| 流转 | 任务状态 | 车辆状态 | 司机状态 |
|---|---|---|---|
| CREATED → ASSIGNED | ASSIGNED | IDLE → ON_DUTY | AVAILABLE → ON_DUTY |
| ASSIGNED → STARTED | STARTED | 保持 ON_DUTY | 保持 ON_DUTY |
| STARTED → COMPLETED | COMPLETED | ON_DUTY → IDLE | ON_DUTY → AVAILABLE |
| → CANCELLED | CANCELLED | ON_DUTY → IDLE | ON_DUTY → AVAILABLE |

- 任务完成/取消后，关联订单状态同步更新（DELIVERED / 回退 PENDING）
- 任务记录总里程 totalDist、总成本 totalCost，停靠点序列即算法输出路线

### 3.5 FR-4 VRP 路径优化（核心）

**算法实现说明**：本模块全部使用启发式遗传算法；开发阶段三个算法均需要完成参数调优。
- CVRP-GA：调优种群规模、交叉概率、变异概率、迭代终止条件，避免早熟收敛。
- VRPTW-GA：在遗传参数基础上额外调优时间窗惩罚系数，平衡总距离与时间窗违约。
- NSGA-II 多目标：调优种群、迭代代数、非支配排序、拥挤度计算参数，输出分布合理的 Pareto 解集。

**输入**
- 待配送订单集合（含客户经纬度、时间窗、货重/体积）
- 可用车辆集合（含载重/容积上限）；可选：配送中心坐标

**处理**
| 算法 | 场景 | 约束/目标 |
|---|---|---|
| CVRP-GA | 基础容量约束 | 车辆容量不超限，最小化总行驶距离 |
| VRPTW-GA | 容量 + 时间窗 | 时间窗违约计入惩罚，最小化总距离 + 惩罚 |
| NSGA-II | 多目标优化 | 同时优化：总距离 / 使用车辆数 / 时间窗违约，输出 Pareto 解集 |

**输出**
- 每辆车的访问站点序列（即 DispatchStop 的 seq 排序）
- 每条路线的总距离、总成本；多目标模式下输出 Pareto 前沿供调度员选择
- 提供 REST API：`POST /vrp/optimize`（输入订单/车辆 → 输出路线），结果一键写入调度任务

### 3.6 FR-5 配送实时跟踪

- 通过 WebSocket（socket.io）向前端推送任务状态变更、车辆/订单状态变更事件
- 前端收到事件后动态刷新地图上的车辆位置与任务状态，无需手动刷新页面

### 3.7 FR-6 地图可视化

- 基于**百度地图 SDK**，在地图上展示：客户分布点、车辆当前位置、优化后的路线。课程演示使用百度开发者免费配额；商用会产生 API 调用费用。
- 支持查看单个调度任务的完整路线与各停靠点到达情况

### 3.8 FR-7 统计分析仪表盘

| 指标 | 说明 |
|---|---|
| 配送完成率 | DELIVERED 订单数 / 总订单数 |
| 车辆利用率 | ON_DUTY 车辆数 / 可用车辆总数 |
| 平均配送耗时 | 任务 startTime 至 endTime 的均值 |
| 时间窗满足率 | 无违约送达的停靠点占比 |

```mermaid
    STARTED --> COMPLETED: 全部送达
    COMPLETED --> [*]
    CREATED --> CANCELLED: 取消
    ASSIGNED --> CANCELLED: 取消
    STARTED --> CANCELLED: 取消
    CANCELLED --> [*]
    note right of ASSIGNED: 车辆/司机转 ON_DUTY
    note right of COMPLETED: 车辆转IDLE、司机转AVAILABLE、订单转DELIVERED
    note right of CANCELLED: 释放车辆/司机、订单回退PENDING
```

**路径优化接口时序图**

```mermaid
sequenceDiagram
    participant D as 调度员
    participant F as 前端
    participant V as VRP 控制器
    participant A as 优化算法
    participant DB as 数据库
    D->>F: 选择订单/车辆/算法
    F->>V: POST /vrp/optimize
    V->>DB: 读取客户经纬度/时间窗
    DB-->>V: 订单与车辆数据
    V->>A: 构造距离矩阵并求解
    A-->>V: 路线方案 / Pareto 解集
    V-->>F: 返回路线
    F-->>D: 地图预览
    D->>F: 确认方案
    F->>V: 创建调度任务
    V->>DB: 写入任务与停靠点
```

## 5. 界面草图或主要界面说明

前端采用 Vue3 + **百度地图 SDK** + ECharts，共 5 个主要界面：

### 5.1 基础数据管理页（客户/车辆/司机）
- 布局：左侧导航 + 数据表格 + "新增/编辑"弹窗表单
- 要点：列表分页与搜索、删除二次确认、必填项即时校验、车牌/驾驶证号重复返回 409 提示

### 5.2 订单管理页
- 布局：状态筛选标签（PENDING/ASSIGNED/IN_TRANSIT/DELIVERED/FAILED/CANCELLED）+ 订单表格
- 要点：新增订单下拉选择客户、详情含客户信息、仅 PENDING 订单可编辑/取消

### 5.3 路径优化页（核心界面）
- 布局：左侧参数面板（订单多选、车辆多选、算法选择 CVRP-GA/VRPTW-GA/NSGA-II）+ 右侧地图预览
- 要点：一键求解、不同车辆路线不同颜色渲染、多目标模式展示 Pareto 前沿表格、"确认生成调度任务"按钮

### 5.4 调度任务页
- 布局：任务列表（状态徽标）+ 任务详情抽屉（车辆/司机/停靠点序列）
- 要点：状态流转操作按钮（分配/开始/完成/取消）、停靠点地图路线查看

### 5.5 统计仪表盘
- 布局：顶部 4 个指标卡片（配送完成率、车辆利用率、平均配送耗时、时间窗满足率）+ 下方 ECharts 图表
- 要点：按时间范围筛选、图表联动刷新

## 6. 数据需求

核心数据实体与关键数据项（完整字段定义见[系统设计文档](02-系统设计文档.md)第 4 章）：

| 实体 | 关键数据项 | 关键约束 |
|---|---|---|
| Customer 客户 | name、phone、address、lng/lat 经纬度、时间窗起止、serviceTime | 经纬度必填（路径优化依赖） |
| Order 订单 | customerId、weight、volume、priority、status | customerId 外键；仅 PENDING 可参与调度 |
| Vehicle 车辆 | plate、capacityW、capacityV、status | plate 全局唯一 |
| Driver 司机 | name、phone、license、status | license 全局唯一 |
| DispatchTask 调度任务 | vehicleId、driverId、status、startTime/endTime、totalDist、totalCost | 车辆/司机外键；状态联动 |
| DispatchStop 停靠点 | taskId、orderId、seq、lng/lat、arrived | seq 为访问顺序，即算法输出路线 |

数据规模约定（课程演示环境）：客户 ≤ 100、订单 ≤ 500、车辆 ≤ 20、司机 ≤ 20。

## 8. 业务规则与约束

### 8.1 业务规则

| 编号 | 规则 |
|---|---|
| BR-1 | 司机驾驶证号 license 全局唯一，重复创建返回 409 |
| BR-2 | 车牌号 plate 全局唯一 |
| BR-3 | 维修中车辆、非 AVAILABLE 司机不可被分配新任务 |
| BR-4 | 任务状态流转必须严格按状态机执行，非法流转返回 400 |
| BR-5 | 车辆/司机/订单状态随任务状态自动联动，不允许人工单独跳改造成不一致 |
| BR-6 | 仅 PENDING 订单可加入路径优化；已被任务占用的订单不可重复分配 |

### 8.2 技术约束

- 后端：NestJS 10 + TypeScript + Prisma 5 + PostgreSQL（PostGIS）
- 接口文档：Swagger（`/api/docs`）
- 前端：Vue3/React + 地图 SDK + ECharts
- 数据库访问统一走 PrismaService，Schema 变更必须提交 migration
