# 成果查看与使用说明

## 1. 当前成果

智慧物流配送与路径优化平台后台已支持客户、订单、车辆、司机和调度任务管理，以及 CVRP-GA、VRPTW-GA、NSGA-II 路线优化预览、确认方案生成任务、开始/完成/取消配送的状态联动。

Swagger 是接口文档和测试页面，能直接调用后台并查看结果。当前交付为后端功能与实验材料，地图等前端仍需接入；尚未部署公共访问网站。

## 2. 如何打开 Swagger 页面？需要安装什么？

### 方式一：查看现场演示

通过共享屏幕或在运行电脑上打开 http://localhost:3000/api/docs 即可观看。不需要在观看者电脑安装开发环境。

### 方式二：同一局域网用浏览器访问

访问者一般只需 Edge、Chrome 等浏览器，不需要安装 Node.js 或 Docker。提供服务的电脑需要先启动 Docker 和后端，并在访问期间保持运行。

1. 在提供服务的电脑上打开 PowerShell，执行 ipconfig。
2. 找正在使用的 Wi-Fi 或以太网适配器的 IPv4 地址，不使用 Docker 等虚拟网卡地址。
3. 访问者在浏览器输入 http://实际IPv4地址:3000/api/docs 。例如地址为192.168.1.23时，输入 http://192.168.1.23:3000/api/docs；这个地址仅为示例，不能照抄。
4. 若打不开，先在服务电脑确认 localhost 页面能打开，再核对双方网络、服务监听和防火墙。校园网络可能隔离设备，同一个Wi-Fi不保证互通。不要关闭整个防火墙。

localhost 表示浏览器所在的电脑，不能把 localhost 地址当作其他电脑的访问地址。此方式尚需在实际网络中验证。当前开发接口无登录鉴权，不应直接公开到互联网。

### 方式三：在本机独立运行

需要完整项目源码、Node.js、pnpm、Docker Desktop；建议用 VS Code 查看修改代码，通过 Git 获取分支。本机验证使用 Node 24 系列，团队应统一经过验证的版本。

首次需安装依赖、参照 .env.example 配置本地环境、启动数据库、生成 Prisma Client、应用项目迁移并核对 PostGIS。首次配置应按本机情况完成，不能用数据库 reset 代替常规安装。

环境配置好后，在项目根目录执行：

```powershell
docker compose up -d
cd backend
pnpm.cmd run start:dev
```

等待 Nest application successfully started 后打开 http://localhost:3000/api/docs。保留后端终端运行。

单独运行合成算法实验，只需 Node.js、pnpm 和已安装的项目依赖，不需要 Docker 或后端服务。

### 方式四：不同网络通过公共网址访问

需要另外部署服务器并配置访问控制，目前未完成。GitHub 分支只分享代码，不会自动把后端部署成网站。

## 3. 打开页面后如何看成果？

1. 展开 GET /dispatch-tasks，点击 Try it out → Execute，查看已有任务。
2. 取实际任务编号，在 GET /dispatch-tasks/{id} 输入，点击 Execute。
3. 在 Server response → Response body 查看最外层 status，以及 vehicle、driver、stops 和订单状态。
4. 接口文档底部的 Responses 是预设说明；本次实际结果以 Server response 为准。
5. 测试优化时先查询当前 PENDING 订单和 IDLE 车辆，再调用 POST /vrp/optimize；参数与流程见联调说明。

共享服务连接同一数据库：POST、PATCH、DELETE 可能改变数据。先用 GET 查看；确认方案和模拟配送前约定测试数据，避免多人修改同一批订单。

独立运行的数据库可能为空，不会自动带有演示订单1～6。数据不会随 GitHub 源码自动迁移。重启会使内存里的 previewId 失效，但已保存的任务仍在数据库中。

## 5. 常用英文和状态词典

### 接口和操作

| 英文 | 含义 |
|---|---|
| Request / Request body | 请求 / 发给后端的内容 |
| Response / Response body | 回复 / 后端返回内容 |
| Server response | 本次实际执行结果 |
| Responses | 也用作文档里的预设响应说明，不能据此判断执行成功 |
| Try it out / Execute | 开始填写 / 执行 |
| Cancel / Reset / Clear | 退出编辑 / 重置输入 / 清除展示；Swagger 的 Cancel 不是取消调度任务 |
| GET / POST / PATCH / DELETE | 查询 / 提交或创建 / 部分更新 / 删除 |
| 200 / 201 | 请求成功 / 创建成功，不表示配送完成 |
| 400 / 404 / 409 / 410 / 500 | 请求不合要求 / 未找到 / 冲突 / 预览失效 / 后端异常 |
| JSON | 按字段名称组织的数据格式 |
| null / [] / true / false | 无值 / 空列表 / 是 / 否 |

### 业务状态

| 对象 | 英文 | 意思 |
|---|---|---|
| 订单 | PENDING | 待分配 |
| 订单 | ASSIGNED | 已分配 |
| 订单 | IN_TRANSIT | 运输中 |
| 订单 | DELIVERED | 已送达 |
| 订单 | FAILED | 配送失败，枚举中保留 |
| 订单 | CANCELLED | 订单本身取消 |
| 任务 | CREATED | 创建的草稿 |
| 任务 | ASSIGNED | 已分配，待开始 |
| 任务 | STARTED | 配送已开始 |
| 任务 | COMPLETED | 已完成 |
| 任务 | CANCELLED | 任务已取消，当前流程把订单恢复待分配 |
| 车辆 | IDLE / MAINTENANCE | 空闲 / 维修中 |
| 司机 | AVAILABLE / OFF | 可安排 / 不在岗 |
| 车辆或司机 | ON_DUTY | 已占用、执行任务中 |

一个回复可能有多个 status。最外层属于任务，vehicle 里属于车辆，order 里属于订单。取消任务不等于取消订单，订单可能还要重新配送。

### 路线字段

| 字段 | 含义 |
|---|---|
| routes / stops / seq | 车辆路线 / 停靠点 / 停靠顺序 |
| orderIds / vehicleId / driverId | 订单编号列表 / 车辆编号 / 司机编号 |
| previewId / solutionId / previewOnly | 预览编号 / 方案编号 / 仅预览 |
| depot / returnToDepot | 仓库出发点 / 是否回仓 |
| lng / lat / WGS84 | 经度 / 纬度 / 坐标系统名称 |
| totalDistance / totalDist | 预览总距离 / 任务总距离，本项目单位为米 |
| totalCost | 费用；null 是未计算，不是0元 |
| totalWeight / totalVolume | 重量 / 体积合计，单位需与车辆容量一致 |
| capacityW / capacityV | 重量 / 体积容量 |
| usedVehicleCount | 使用车辆数 |
| timeWindowStart / timeWindowEnd | 服务时间窗开始 / 结束 |
| arrivalTime / serviceStartTime | 预计到达 / 预计开始服务时间 |
| departureTime / serviceTime | 出发或离开时间 / 每单服务时长 |
| waitingMinutes / lateMinutes | 等待 / 迟到分钟数 |
| totalLateMinutes / allTimeWindowsSatisfied | 总迟到分钟数 / 是否全部未超窗 |
| startTime / endTime | 任务实际操作开始 / 结束时间 |
| arrived | 标记到达，当前模拟完成任务时统一设为true |

算法时间按午夜起分钟数：480=08:00，1080=18:00，超过1440表示跨天。任务 ISO 时间尾部 Z 表示 UTC，北京时间加8小时。实际操作时间与算法预计时间不同。

### 算法名称

| 名称 | 英文全称与通俗解释 |
|---|---|
| VRP | Vehicle Routing Problem：车辆路径问题，安排车辆与配送顺序 |
| CVRP | Capacitated Vehicle Routing Problem：加入装载容量限制 |
| VRPTW | Vehicle Routing Problem with Time Windows：加入服务时间窗 |
| GA | Genetic Algorithm：遗传算法，多轮选择、组合和改变候选方案 |
| CVRP-GA | 用遗传算法处理容量约束，本项目优化距离 |
| VRPTW-GA | 用遗传算法处理时间窗，本项目优化距离和迟到惩罚 |
| NSGA-II | Non-dominated Sorting Genetic Algorithm II：非支配排序遗传算法II，返回多个目标之间有取舍的方案 |
| Pareto / non-dominated | 帕累托 / 非支配：没有另一个候选在所有目标都不差且至少一个更好 |
| seed | 随机种子，便于重复实验 |
| penaltyPerMinute | VRPTW每迟到一分钟的等效距离惩罚，不是罚款金额 |
| FOUND / NOT_FOUND | 本次找到完整容量可行方案 / 未找到；未找到不等于证明无解 |
| SPHERICAL | 球面距离模型，不是实际道路里程 |
| APPROXIMATE_SEARCH_FRONT | 本次搜索的近似前沿，不保证全局最优 |

FOUND 不保证零迟到。当前时间窗是软约束：提前到达等待，服务开始超窗计算迟到。NSGA-II 多个方案不是报错，也不能只凭方案数量判断算法优劣。
