# 项目实施过程材料

本项目由 Vue 3 + Vite 前端、NestJS REST/Socket.IO 后端、Prisma ORM、PostgreSQL/PostGIS 数据库和 CVRP/VRPTW/NSGA-II 启发式算法组成。浏览器端提供基础数据管理、路线地图、任务状态流转和运营仪表盘。系统用于课程演示，不含用户登录、车辆 GPS 硬件或生产级道路导航。本章记录开发过程、版本发布、阶段性测试成果与问题解决；环境搭建与演示操作见文末附录。

## 二、Git 协作规范与提交记录

### 2.1 协作规范

- 分支保护：`main` 与 `dev` 均开启保护，禁止直接 push、禁止强推与删分支，合并必须走 PR 且至少 1 人 Review。
- 分支命名：成员工作分支遵循 `feat/[模块名]`（如 `feat/orders-crud`、`feat/vrp-nsga2`）。
- 提交信息：遵循 `feat(backend): [变更描述]` 等 Conventional Commits 格式。
- 行尾统一：仓库根目录 `.gitattributes` 统一为 LF，避免跨平台协作冲突。
- 重大变更流程：需求/设计文档变更 → 提 PR → 组内 Review → 合入 `dev`；阶段性稳定版由 `dev` 发起 release PR 合入 `main`。
- 工具限制说明：校园网环境下 `api.github.com` 不可达，`gh` 命令行不可用，所有 PR 创建与 Review 通过 GitHub 网页完成。

### 2.2 提交记录摘要

完整提交历史可随时在仓库复核：

```powershell
git log --pretty=format:"%h|%ad|%an|%s" --date=short --no-merges
```

由于阶段性采用 Squash 合并，多人提交会归并到合并者名下，因此贡献统计以 [项目总结报告](07-项目总结报告.md) 第 8 节的主责交付物为准，不以提交数量衡量。

## 五、主要工程问题及解决

以下为开发过程中影响协作效率或阻碍推进的工程问题（功能缺陷的闭环记录见 [测试文档](05-测试文档.md) 第 8 节）：

1. **PostGIS 扩展安装失败**：Stack Builder 在线安装多次失败 → 改用官方离线安装包，一次成功。
2. **NestJS 依赖版本混用**：v10 与 v12 混装导致 peer 依赖冲突 → 全项目统一到 v10 系列。
3. **PowerShell 编码问题**：PowerShell 5.x 默认输出带 BOM，导致 Prisma schema 与 .env 解析失败 → 创建文件时改用无 BOM UTF-8 编码。
4. **Prisma 版本不匹配**：客户端与 CLI 版本不一致导致初始化失败 → 统一为 5.x，并用 `pnpm exec` 替代 `npx` 避免临时拉取最新版。
5. **校园网限制**：`api.github.com` 不可达，`gh` CLI 与部分命令行 PR 操作失败 → 全部 PR 与 Review 改走 GitHub 网页。
6. **百度地图加载异常**：使用 `127.0.0.1` 访问触发 AK 域名校验失败；SDK 加载地址错误导致 BMapGL 未定义 → 统一使用 `localhost` 域名访问，SDK 固定为官方 WebGL 加载地址。
7. **e2e 污染演示库**：早期 e2e 直连演示库产生脏数据 → 建立专用 logistics_test 测试库，禁止在演示库运行 e2e。
8. **本地变更阻塞拉取**：未提交的本地文件改动导致 `git pull` 中止 → 团队约定先 `git stash` 再拉取，共享分支冲突优先 `git merge origin/dev` 而非 rebase。

## 附录 A：环境准备

- Node.js 与 pnpm
- Docker Desktop（用于 PostgreSQL/PostGIS；Redis 容器暂未接入业务）
- 百度地图浏览器端 AK，网站白名单覆盖运行前端的域名

## 附录 B：首次启动

1. 在项目根目录运行 `docker compose up -d postgres`。
2. 在 `backend` 将 `.env.example` 复制为 `.env`，确认 `DATABASE_URL` 指向本地数据库。
3. 在 `backend` 运行 `pnpm.cmd install`、`pnpm.cmd exec prisma generate` 和 `pnpm.cmd exec prisma migrate deploy`。迁移负责创建数据表并启用 PostGIS。
4. 在 `frontend` 将 `.env.example` 复制为 `.env.local`，设置 `VITE_BAIDU_MAP_AK`。
5. 如数据库为空，在 `backend` 运行 `pnpm.cmd run seed:demo`。脚本只对空业务库写入演示数据，不会清空已有记录。
6. 在两个终端分别运行后端 `pnpm.cmd run start:dev` 与前端 `pnpm.cmd run dev`。
7. 浏览器打开 Vite 显示的地址（默认 `http://localhost:5173`）；Swagger 在 `http://localhost:3000/api/docs`。

## 附录 C：演示流程

1. 在“基础数据”检查客户、订单、车辆、司机；先建客户才能建订单。
2. 在“地图可视化”选择待分配订单和空闲车辆，运行一种算法预览路线。
3. 为每条使用中的路线分配不同的可用司机，确认方案生成调度任务。
4. 在“调度任务”依次开始、完成或取消配送；状态更新会联动车辆、司机、订单并通过 Socket.IO 通知前端。
5. 在“运营仪表盘”查看汇总。

## 附录 D：已知限制

路线线段按球面距离模型绘制，不代表真实道路导航；地图显示前将接口 WGS84 坐标转换为百度地图 BD09。任务通知不含 GPS 位置，不保证断线期间的事件补发；前端重连后通过 REST 重新读取任务快照。未部署公网服务，当前无身份认证，不应暴露到互联网。
