# 实时状态接口与验收

## 已补代码

运行项目 backend/src/tracking 提供 TrackingGateway 和 TrackingModule。确认任务和更新任务在数据库事务成功后发送 task.updated。当前事件是任务状态通知，不包含 GPS 位置，也不是历史消息队列。

## 前端接入

前端项目安装 socket.io-client，使用以下代码。BASE_URL 替换为可访问的后端地址；其他电脑不能用 localhost 访问开发者电脑。

```js
import { io } from 'socket.io-client';
const BASE_URL = 'http://localhost:3000';
const socket = io(`${BASE_URL}/tracking`);

async function refreshTask(id) {
  const response = await fetch(`${BASE_URL}/dispatch-tasks/${id}`);
  if (!response.ok) throw new Error(`查询任务失败：${response.status}`);
  return response.json();
}

socket.on('connect', () => {
  // 首次连接和断线重连后，重新请求任务列表/当前任务作为最新状态。
});
socket.on('task.updated', async event => {
  try {
    const task = await refreshTask(event.taskId);
    console.log('最新任务', task); // 在此更新前端状态和页面
  } catch (error) {
    console.error(error);
  }
});
socket.on('connect_error', error => console.error('连接失败', error.message));
// 页面销毁时调用 socket.disconnect()。
```

事件示例：

```json
{"taskId":1,"status":"STARTED","vehicleId":1,"driverId":1,"emittedAt":"2026-10-15T00:00:00.000Z"}
```

事件不保证断线补发或业务顺序。收到事件后查询 REST 最新状态；生产前端应避免较旧的查询响应覆盖较新的响应。同一状态重复更新也可能触发通知，应允许重复刷新。

## 验证步骤

1. 在运行项目 backend 目录执行 `pnpm.cmd test -- --runInBand`，保存测试汇总。
2. 执行 `pnpm.cmd run build`，确认编译无错误。
3. 启动后端；由前端客户端连接 /tracking，确认出现 connect。
4. 用演示数据确认一个新任务，验证收到 ASSIGNED 通知。
5. 按现有 Swagger 接口依次启动、完成任务，验证 STARTED、COMPLETED 通知，并重新 GET 检查状态。
6. 对已经完成的任务尝试非法状态流转：接口应拒绝，不应发送成功通知。
7. 断开客户端，修改另一演示任务后重连；通过 GET 恢复状态，不能依赖补发旧事件。

不要用真实配送任务做状态修改测试。只查看页面不等于验证状态推送成功。
